# 🔐 Secure Chat — مشروع تعليمي في الأمن السيبراني

مشروع دردشة يوضّح **كيف تنتقل البيانات في العصر الحالي**، مبني بلغة **Python**
ومكتبة **socket** من الصفر، مع إمكانية **تشغيل/إطفاء كل خاصية أمنية** لرؤية
تأثيرها مباشرة في **Wireshark**.

> ⚠️ **تنبيه مهم:** كل الخوارزميات المكتوبة يدوياً هنا **تعليمية فقط** ولا يجوز
> استخدامها في الإنتاج. راجع قسم «ملاحظات أمنية» في الأسفل.

---

## 🎯 متطلبات المعلم وكيف تحققت

| المتطلب | الخاصية الأمنية | كيف حققناه |
|---------|------------------|-------------|
| **السرية** (Confidentiality) | إخفاء المحتوى | RC4 (يدوي)، AES-ECB/CBC/CTR/GCM (يدوي) |
| **السلامة** (Integrity) | كشف أي تعديل | HMAC-SHA256 (يدوي) + GCM tag |
| **المصادقة** (Authentication) | التحقق من الهوية | توقيع ECDSA P-256 + تثبيت المفتاح العام |
| **تبادل المفاتيح** | توليد مفتاح مشترك | ECDH (X25519 + P-256) |
| **الالتزام بـ socket** | نقل البيانات | سيرفر TCP خام + مصافحة WebSocket يدوية |

---

## 🏗️ البنية العامة

```
العميل (بايثون / متصفح)
      │
      │  1) HELLO      → يرسل مفتاحه العام (ECDH)
      │  2) HELLO_ACK  ← مفتاح السيرفر العام + توقيع ECDSA
      │  3) اشتقاق مفتاحين: واحد للتشفير وآخر للسلامة (HKDF)
      ▼
   مفتاح مشترك (لا يُرسل أبداً على الشبكة)
      │
      │  كل رسالة:  [تشفير] ثم [HMAC]  ← Encrypt-then-MAC
      ▼
السيرفر يعيد التشفير لكل عميل بمفتاحه الخاص (لأن كل جلسة ECDH مستقلة)
```

### أنواع العملاء

| العميل | النقل | التشفير المتاح |
|--------|-------|-----------------|
| **بايثون** (`client.py`) | TCP خام | RC4, AES-ECB, CBC, CTR, GCM + HMAC |
| **المتصفح** (`/chat`) | WebSocket يدوي | AES-GCM (عبر Web Crypto API) |

## 🚀 التشغيل

### 1) التثبيت

```bash
pip install -r requirements.txt
```

### 2) تشغيل السيرفر

```bash
python server.py            # المنفذ الافتراضي 5000
python server.py --port 8000
```

عند التشغيل ستظهر لك عناوين:
- **لوحة التحكم:** `http://localhost:5000/settings`
- **دردشة المتصفح:** `http://localhost:5000/chat`
- **عميل بايثون:** يشير إلى المنفذ 5000

### 3) تشغيل العملاء

**عميل بايثون:**
```bash
python client.py --name ali
python client.py --name sara --port 5000
```

**المتصفح:** افتح `/chat` وأدخل اسمك.

## ⚙️ إعدادات التبديل (أهم جزء تعليمي)

كل الإعدادات في `config.py`، ويمكن تغييرها من **لوحة التحكم** أو بمتغيرات بيئة:

```bash
ENCRYPTION=0 python server.py      # نص واضح تماماً في Wireshark
CIPHER=AES-ECB python server.py    # لكشف الأنماط المتكررة
INTEGRITY=0 python server.py       # تعديل البيانات يمرّ دون كشف
```

| الإعداد | القيم | ماذا يتحكم |
|---------|-------|------------|
| `ENCRYPTION` | on / off | هل نشفّر أصلاً |
| `CIPHER` | `RC4`, `AES-ECB`, `AES-CBC`, `AES-CTR`, `AES-GCM` | وضع التشفير |
| `INTEGRITY` | on / off | هل نتحقق من السلامة |
| `MAC_MODE` | `HMAC`, `GCM` | طريقة السلامة |
| `AUTHENTICATION` | on / off | هل نتحقق من توقيع السيرفر |
| `KEY_EXCHANGE` | `ECDH`, `HARDCODED` | تبادل المفاتيح |

## 🔬 تجارب Wireshark

شغّل Wireshark، واختر الواجهة `Loopback` (lo)، وفلتر:
```
tcp.port == 5000
```
ثم **اتبع هذه التجارب بالترتيب** — كل واحدة تعلّمك درساً:

### التجربة 1: لا تشفير (النص واضح 😱)

```bash
ENCRYPTION=0 python server.py
python client.py --name ali
```
اكتب: `كلمة السر هي 1234`

في Wireshark → كليك يمين على الحزمة → **Follow → TCP Stream**
> 🔎 **سترى الرسالة كاملة بالنص الواضح!** هكذا تُقرأ البيانات غير المشفّرة.

---

### التجربة 2: تشفير AES-CTR (لا تُقرأ ✅)

```bash
CIPHER=AES-CTR python server.py
```
نفس الرسالة → في Wireshark سترى **بايتات عشوائية** لا معنى لها.

---

### التجربة 3: كشف الأنماط في ECB (الأخطر 🔴)

```bash
CIPHER=AES-ECB python server.py
```
اكتب رسالة طويلة فيها تكرار، مثل:
`AAAAAAAAAAAAAAAA AAAAAAAAAAAAAAAA`

> 🔎 **ستلاحظ أن الكتل المتشابهة تنتج بايتات متطابقة!** هذا هو عيب ECB الشهير
> (تذكّر صورة البطريق). جرّب نفس الشيء مع CBC ولن ترى التكرار.

---

### التجربة 4: السلامة — تعديل البيانات

**أ) السلامة مطفأة (العبث يمرّ ⚠️):**
```bash
INTEGRITY=0 python server.py
python tools/mitm.py --listen 6000 --target 5000 --tamper
python client.py --port 6000 --name victim
```
اكتب أي رسالة → سترى: **«وصلت بيانات معدّلة ولم يُكتشف العبث»**.

**ب) السلامة مُفعّلة (العبث يُرفض ✅):**
```bash
INTEGRITY=1 python server.py
python tools/mitm.py --listen 6000 --target 5000 --tamper
python client.py --port 6000 --name victim
```
نفس الرسالة → سترى: **«رُفضت رسالة: HMAC: فشل التحقق»**.

> 🔎 **هذا هو الفرق بين وجود السلامة وغيابها!**

### التجربة 5: المصادقة

```bash
AUTHENTICATION=0 python server.py
```
سيرفض العميل التحقق من هوية السيرفر → عرضة لهجوم رجل-في-المنتصف الحقيقي
(لأن المهاجم يستطيع انتحال شخصية السيرفر).

## 📚 الدروس الأساسية

### 1. RC4 (stream cipher)
يولّد **تدفق مفاتيح** (keystream) من المفتاح، ثم يدمجه مع النص بـ XOR.
التشفير وفك التشفير نفس العملية.

### 2. HMAC
`HMAC(K, m) = H((K ⊕ opad) ‖ H((K ⊕ ipad) ‖ m))`
- لا **يُشفّر** — بل يضمن **السلامة** عند وجود مفتاح مشترك.
- المقارنة تتم بزمن ثابت (`compare_digest`) لتجنّب هجوم التوقيت.

### 3. تطوّر أوضاع AES

| الوضع | المبدأ | المشكلة |
|-------|--------|---------|
| **ECB** | كل كتلة مستقلة | يكشف الأنماط |
| **CBC** | XOR مع الكتلة السابقة + IV | تسلسلي (بطيء) |
| **CTR** | يحوّل AES لمجرى (stream) | لا سلامة |
| **GCM** | CTR + GHASH (AEAD) | يحتاج nonce فريد |

### 4. Encrypt-then-MAC
نشفّر أولاً، ثم نحسب HMAC على **النص المشفّر** (لا الأصلي).
هذا هو الترتيب الآمن الوحيد عملياً، وتستخدمه TLS و IPsec.

### 5. ECDH و Forward Secrecy
الطرفان يتبادلان مفاتيح عامة فقط، ويحسبان سرّاً مشتركاً **لا يُرسل أبداً**.
حتى لو سُرّب المفتاح الخاص لاحقاً، الرسائل القديمة تبقى آمنة.

### 6. المصادقة ومنع MITM
ECDH وحده لا يكفي — المهاجم يستطيع عمل جلسة منفصلة مع كل طرف.
الحل: توقيع المفتاح المؤقّت بمفتاح طويل المدى، والعميل يثبّت المفتاح العام مسبقاً
(هذا دور شهادات X.509 في TLS).

## ☁️ النشر على Render (مجاناً)

المشروع جاهز للنشر: منفذ واحد، ويقرأ `PORT` من متغيرات البيئة، ويدعم WebSocket.

### الطريقة 1: عبر لوحة Render (بدون ملفات إعداد)
1. سجّل الدخول إلى [dashboard.render.com](https://dashboard.render.com) بحساب GitHub.
2. **New +** → **Web Service** → اختر مستودع `secure-chat`.
3. الإعدادات:
   - **Language / Runtime**: `Docker`
   - **Instance Type**: `Free`
   - **Health Check Path**: `/settings`
4. اضغط **Create Web Service**. بعد دقيقتين يصبح الرابط جاهزاً:
   `https://secure-chat-xxxx.onrender.com/chat`

### الطريقة 2: عبر Blueprint (يقرأ `render.yaml` تلقائياً)
**New +** → **Blueprint** → اختر المستودع → **Apply**.

### متغيرات البيئة (اختيارية)
| المفتاح | القيمة | الوصف |
|---------|--------|-------|
| `CIPHER` | `AES-GCM` | وضع التشفير الافتراضي |
| `ENCRYPTION` | `1` | تشغيل/إطفاء السرية |
| `INTEGRITY` | `1` | تشغيل/إطفاء السلامة |
| `AUTHENTICATION` | `1` | تشغيل/إطفاء المصادقة |

> 💡 لا تضبط `PORT` يدوياً — Render يضخّه تلقائياً.

### ملاحظات مهمة عند النشر
- **الخطة المجانية تنام** بعد ~15 دقيقة خمول، وأول طلب يستغرق ~30 ثانية للاستيقاظ.
- **مفتاح الهوية يُولَّد جديداً** عند كل إعادة تشغيل (لأن نظام ملفات Render مؤقت).
  بصمة السيرفر تتغيّر، لذا التثبيت (pinning) يعمل فقط أثناء عمر الحاوية الواحد.
- **WebSocket يعمل** عبر `wss://` (Render يدعم WebSocket على الخطة المجانية).
- `.dockerignore` يستثني المفتاح الخاص — لا يُنسخ داخل الصورة أبداً.

## ⚠️ ملاحظات أمنية (مهمة)

1. **الكود اليدوي تعليمي فقط** — RC4 مهجور، والأوضاع المكتوبة يدوياً قد تكون
   عرضة لهجمات جانبية (timing) لا تغطّيها هذه النسخة.
2. **في الإنتاج استخدم TLS** — Python `ssl` أو `cryptography`، أو مكتبة جاهزة.
3. **فصل المفاتيح واجب** — لا تستخدم مفتاحاً واحداً للتشفير والسلامة.
4. **مفتاح السيرفر** (`crypto/server_identity.key`) مُستثنى من Git — لا ترفعه أبداً.
5. **التثبيت (pinning) يدوي هنا** — في TLS تتم إدارته عبر سلاسل شهادات CA.
